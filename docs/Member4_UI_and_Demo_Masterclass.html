4. The Interactive Topology Canvas & Sliding Link Inspector

Figure 2: Clicking any link opens the right-hand Link Inspector panel with real-time sliders for latency, packet loss, and utilization.

4.1 Understanding the Visual Styles on the Canvas:

  • Switches (S1, S2, S3): Dark rounded cards with blue borders and DPID identifiers.
  • Hosts (H1, H2, H3, H4): Circular endpoints showing IP addresses (e.g. 10.0.0.1 to 10.0.0.4).
  • Green Solid Lines: Healthy active links.
  • Amber Solid Lines: Degraded links suffering high latency or loss.
  • Red-Dashed Lines: Failed / severed links (status = DOWN).
  • Neon Cyan Glowing Flowing Line: The ACTIVE FORWARDING ROUTE. Animated using CSS keyframe dash-offsets to represent real packets moving across the path!

4.2 Explaining the Sliding Inspector Window (Right Panel):

When you click on any link (e.g., L_S1_S3), the right panel slides open:

  • Link ID & Endpoints: Shows L_S1_S3 (S1 ↔ S3).
  • Fail Link / Restore Link Button: Manually cuts or restores the link.
  • Latency Slider (1ms - 150ms): Simulates fiber distance or propagation delays.
  • Packet Loss Slider (0% - 50%): Simulates packet drops caused by queue overflow.
  • Utilization Slider (0% - 100%): Simulates traffic bandwidth congestion.
  • 'Apply Metrics Update' Button: Sends POST /api/links/{id}/metrics to re-evaluate the graph.
What to say: "Our interactive inspector allows the operator to select any link and manually test line failures or adjust latency and loss sliders to see the routing engine adapt in real time."

MATH BOX Live Mathematical Cost Formula Box

What it does: Displays the live, interactive cost formula with the currently configured numerical coefficients:

link_cost = (w_cost × C_admin) + (w_latency × [Lat / ref_ms]) + (w_loss × [Loss% / 100]) + (w_util × [Util% / 100])
What to say: "This box shows our normalized composite cost equation updating in real time as the sliders are moved."

The 5 Sliders & Inputs (What Each Does):

Slider / Input Default Value Range What It Does & What You Say
Configured Cost Weight (w_cost) 1.00 0.0 to 5.0 "Controls the importance of administrative hop count. Increasing this makes the algorithm behave more like traditional Dijkstra."
Latency Weight (w_latency) 1.00 0.0 to 5.0 "Penalizes propagation and queuing delays. Useful for interactive audio/video traffic."
Packet Loss Weight (w_loss) 2.00 0.0 to 10.0 "Heavily penalizes drop-prone links. We set it to 2.0 because packet loss causes TCP timeouts and throughput collapse."
Utilization Weight (w_util) 1.50 0.0 to 5.0 "Penalizes saturated links to avoid buffer overflow and distribute traffic evenly."
Latency Reference Normalizer 50 ms 10 to 500 ms "Normalizes milliseconds into decimals: normalized_lat = latency / ref_ms."
SDN PANEL Operating Mode & Ubuntu/WSL2 Real SDN Setup Box

What it does: Displays the current operating status badge (Simulation Mode (Standalone)) and copy-pasteable terminal commands for launching the Ryu OpenFlow 1.3 Controller and Mininet on Ubuntu or Windows Subsystem for Linux (WSL2).

8. The Formula Part: How to Explain It Simply

normalized_latency = latency_ms / 50.0 ms normalized_loss = packet_loss_percent / 100.0 normalized_util = utilization_percent / 100.0 link_cost = (1.0 × C_admin) + (1.0 × norm_latency) + (2.0 × norm_loss) + (1.5 × norm_util)
The 3-Sentence Formula Punchline (Memorize This!):
"We normalize latency against 50ms, and packet loss and utilization into decimals between 0 and 1. We assign the highest weight (2.0) to packet loss because packet drops destroy TCP throughput. When direct link L_S1_S3 suffers 18% loss, its calculated cost spikes from 1.44 to 3.94, making the 4-hop clean route via S2 mathematically cheaper (4.79 vs 6.12)!"
